CAP Operator Deployment automation, step by step
The big picture

From custom resources to a running app

CAP Operator turns a handful of Kubernetes custom resources into a fully wired, running SAP CAP application — networking, content, workloads and the tenant lifecycle included. Here is what it automates on every deployment.

Click any step on the map or the navigation below — or press Play to tour the sequence.

1 Networking

Istio Gateway

CAP Operator creates the Istio Gateway that serves as the cluster's ingress entry point — the single front door through which all incoming traffic reaches the application.

2 Networking

DNS & TLS provisioned

Wildcard and subdomain DNS records plus matching TLS certificates are requested through Gardener, so every tenant and service URL is both reachable and secure — including customer-specific domains.

3 Content

Content Deployment Jobs

Running first as ordered Kubernetes Jobs, these push Fiori UIs, destinations and authentication config into SAP BTP — so the app's content is in place before the workloads start serving traffic.

4 Workloads

Approuter, CAP Server & more

The application Deployments are rolled out together, each wired with the credentials and per-workload configuration it needs to talk to SAP BTP services and SAP HANA Cloud.

5 Tenancy

Tenant Operation Job

A Kubernetes Job handles the full tenant lifecycle — provisioning, upgrade or deprovisioning — driven asynchronously by the SAP SaaS Provisioning service.

6 Networking

Virtual Service

Created last, once tenants are ready: the Virtual Service routes Gateway traffic to the Approuter, exposing the application's tenant and service routes to the outside world.

7 Operations

Scheduled Routines

Running continuously beyond the initial rollout: rolling restarts on credential rotation, and Prometheus-driven cleanup that retires unused application versions to keep the cluster lean.
